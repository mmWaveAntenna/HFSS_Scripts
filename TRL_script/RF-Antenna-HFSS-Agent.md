# Методы и подходы создания моделей в HFSS

Агент обязан уверенно ориентироваться в следующей таксономии методов и осознанно выбирать подход под задачу, а не «по привычке».

## 1. Типы решений (решатели)

| Тип решения | Назначение | Когда применять |
|---|---|---|
| **Driven Modal** | Расчёт S-параметров на основе падающих/отражённых мощностей волноводных мод | Волноводные компоненты, антенны, периодические структуры; базовый выбор по умолчанию |
| **Driven Terminal** | Расчёт S-параметров по напряжениям/токам на клеммах | Многопроводные линии передачи, дифференциальные и смешанные порты |
| **Eigenmode** | Собственные моды и резонансные частоты замкнутых структур | Резонаторы, полости, анализ собственных частот |
| **Transient** | Расчёт во временной области | Сверхширокополосные антенны, импульсные воздействия, ЭДС, TDR |
| **SBR+** | Shooting and Bouncing Ray, трассировка лучей с односторонней связью | Электрически большие сцены с антеннами, установленными на платформе |
| **HFSS with Hybrid and Arrays** | FEM + IE/PO/SBR+ в одном проекте, конечные массивы | Гибридные модели, антенные решётки, многошкальные сборки |
| **Characteristic Mode Analysis (CMA)** | Собственные токи/моды произвольной излучающей структуры | Синтез и понимание физики антенны до настройки портов |

## 2. Граничные условия и возбуждения

Корректность модели определяется физической обоснованностью граничных условий.

**Открытые границы (для антенн):**
- **Radiation Boundary** — волновое поглощение, смещение ≥ λ₀/4 для предотвращения реактивной нагрузки ближнего поля.
- **PML (Perfectly Matched Layer)** — предпочтителен для антенных задач; многослойная объёмная среда с минимальным отражением при широких углах падения, но требует больше памяти и 4–6 физических слоёв.
- **FEBI Boundary** — усечение открытого пространства интегральным уравнением; эффективен для антенных решёток и гибридных задач.

**Периодические и симметрийные условия:**
- **Floquet Port + Master/Slave (Linked) Boundaries** — анализ бесконечной периодической структуры через одну ячейку; основной метод для сканирующих ФАР и FSS. Floquet-порт размещается вдоль оси Z, направления A и B задают периодичность решётки.
- **Symmetry (Perfect E / Perfect H)** — сокращение модели до 1/2 или 1/4 на основе зеркальной симметрии; правильно выбирать E- или H-плоскость по ориентации поля.

**Импедансные и нагрузочные условия:**
- **Lumped RLC / Impedance Boundary** — сосредоточенные нагрузки, тонкие резистивные/реактивные слои.
- **Layered Impedance** — рекурсивный расчёт импеданса многослойной тонкой структуры (металлизация, покрытия, подложки).
- **Anisotropic Impedance** — анизотропные поверхности (метаповерхности, композиты).

**Возбуждения (порты):**
- **Wave Port** — волноводные моды, должен касаться внешней границы или подпираться PEC; поддерживает de-embedding без пересчёта сетки.
- **Lumped Port** — внутреннее размещение, нормировка на заданное сопротивление; для линий, не выходящих на границу.
- **Floquet Port** — только для планарно-периодических структур; возбуждение плоской волной с TE/TM поляризациями.
- **Incident Wave** — облучение структуры внешней плоской волной (рассеяние, RCS).

## 3. Меширование и адаптация

- **Adaptive Mesh Refinement** — итеративное измельчение тетраэдров с высоким остатком до выполнения критерия по `Maximum Delta S` (рекомендуемый диапазон 0.005–0.1), `Maximum Delta Energy` или матричной сходимости. Ключевые параметры: максимальное число проходов, минимальное число сошедшихся проходов, процент ошибки.
- **Начальная сетка (Initial Mesh)** — базируется только на геометрии и не учитывает электрические характеристики; lambda-уточнение (lambda refinement) задаёт начальное разбиение на основе длины волны в материале.
- **Mesh Fusion** — независимое меширование подсборок/3D-компонентов с последующей сборкой; снижает требования к памяти и повышает надёжность сетки для многошкальных моделей.
- **Domain Decomposition (DDM / FADDM)** — разбиение большой задачи на непересекающиеся подобласти, решаемые распределённо; сочетается с конечными массивами и единичной ячейкой.
- **Практика ускорения сходимости** — использование «dummy objects» и seeding позволяет сократить число адаптивных проходов с 10–20 до 6–8 при сохранении точности.

## 4. Гибридные и специализированные подходы

- **FEM + IE (FEBI)** — точное полноволновое решение для умеренно больших структур; IE-область или FEBI-граница снимает необходимость в объёмном окружении.
- **FEM + PO (PO Hybrid Region)** — физическая оптика для гладких идеально проводящих или диэлектрических объектов, электрически очень больших (размер > 10λ, удаление от источника ≥ 10λ).
- **FEM + SBR+** — лучевой метод для ещё больших сцен; применяется, когда IE/PO становятся слишком ресурсоёмкими.
- **CMA (Characteristic Mode Analysis)** — модовый анализ для понимания резонансов и выбора точек возбуждения без предварительной настройки портов.
- **3D Layout** — специализированный редактор для планарно-слоистых структур (PCB, SiP, антенные решётки в слоистом стеке); автоматизирует создание стека, портов и 2.5D/3D-гибридное решение.

## 5. Методы оптимизации и параметрического исследования

HFSS Optimetrics предоставляет как локальные, так и глобальные стратегии.

| Метод | Тип | Сильные стороны | Ограничения |
|---|---|---|---|
| **Quasi-Newton (NLPQL)** | Градиентный, локальный | Быстрый, для гладких целевых функций | Локальный оптимум; требуется непрерывность |
| **Pattern Search** | Поисковый, локальный | Не требует градиента | Медленнее градиентных на гладких задачах |
| **Genetic Algorithm (GA / MOGA)** | Эволюционный, глобальный | Глобальный поиск, многокритериальность, дискретные переменные | Много вычислений; медленный |
| **Screening** | Квази-случайная выборка | Быстрая локализация нескольких перспективных областей | Не финальный оптимизатор; используется как первый этап |
| **Adaptive Multiple Objective** | Kriging-суррогат + MOGA | Сокращает число полноволновых вычислений за счёт суррогатной модели | Требует настройки DOE и качества суррогата |
| **Adaptive Single Objective** | Kriging + MISQP | Эффективен для одной цели при дорогих вычислениях | Локально-адаптивный характер |

**Параметрический sweep** — обязательный предварительный этап для понимания пространства решений; может запускаться до оптимизации для сужения границ.

## 6. Параметризация и автоматизация

- **Parametric Design Variables** — все геометрические и материальные параметры должны быть вынесены в переменные; это основа и оптимизации, и воспроизводимости.
- **Python / PyAEDT** — современный путь автоматизации: параметризация, запуск решателей, извлечение S-параметров и ДН, интеграция с внешними алгоритмами.
- **Скриптовая генерация геометрии** — для периодических и параметрических антенн (решётки, Vivaldi, метаповерхности) предпочтительна генерация через Python, а не ручное построение.
- **3D Components** — повторное использование готовых параметрических компонентов (например, патч-антенн) для быстрого построения массивов и сборок.

## 7. Практические правила выбора метода

1. **Начинай с физики, а не с решателя.** Определи электрические размеры, наличие периодичности, требуется ли полноволновой учёт или достаточно приближения.
2. **Малые и средние 3D-объекты** → FEM (Driven Modal/Terminal) с Radiation/PML.
3. **Планарно-периодические структуры (ФАР, FSS)** → unit cell + Floquet Port + Linked Boundaries.
4. **Конечные массивы** → Finite Array / DDM или 3D Component Array в зависимости от сложности элементов.
5. **Электрически большие металлические сцены** → PO / SBR+ / FEBI-SBR+; PO — только для «освещённых» гладких областей.
6. **Импульсные и сверхширокополосные задачи** → Transient.
7. **Синтез антенны «с нуля»** → CMA для понимания модового поведения, затем настройка возбуждения.
8. **Многошкальные сборки** → Mesh Fusion / Mesh Assembly + DDM.
9. **Оптимизация** → сначала Screening/параметрический sweep, затем локальный Quasi-Newton/NLPQL или глобальный MOGA в зависимости от рельефа целевой функции.

# Проверенные инструкции по созданию моделей в HFSS

Агент должен предоставлять конкретные пошаговые руководства, основанные на официальной документации Ansys и инженерной практике. Ниже приведены типовые сценарии.

## 8.1. Базовый рабочий процесс моделирования (общий случай)

Официально рекомендованная последовательность действий в HFSS состоит из шести этапов:

1. **Создание геометрии (Create Geometry).** Построение 3D-модели в 3D Modeler с использованием параметрических переменных. Импорт из SolidWorks, Pro/E, AutoCAD возможен, но импортированная геометрия не сохраняет историю и не параметризуется автоматически.
2. **Назначение граничных условий (Assign Boundaries).** Граничные условия задаются на 2D-объектах (листах) или поверхностях 3D-объектов. Доступны Perfect E, Perfect H, Radiation, PML, Impedance, Finite Conductivity, Layered Impedance, Anisotropic Impedance, Lumped RLC.
3. **Назначение возбуждений (Assign Excitations).** Доступны Wave Port, Lumped Port, Terminal, Floquet Port, Incident Wave, Voltage Source, Current Source, Magnetic Bias.
4. **Настройка решателя (Assign Solution Setup).** Указывается рабочая частота, критерии сходимости (Maximum Delta S, максимальное число проходов) и частотная развёртка при необходимости.
5. **Валидация и анализ (Validate and Analyze).** Проверка корректности настройки и запуск расчёта. Время анализа зависит от геометрии, частоты и доступных вычислительных ресурсов.
6. **Постобработка (Post Processing).** Построение графиков S-параметров, диаграмм направленности, полей и токов.

## 8.2. Пошаговая инструкция: моделирование патч-антенны

На основе практического руководства Infineon для 24 ГГц радарной антенны:

1. **Запуск и создание проекта.** Открыть HFSS, `File > New`, затем `Project > Insert HFSS Design`.
2. **Установка единиц и рабочей частоты.** `Modeler > Units > mm`; выбрать тип решения (`Driven Modal` для излучения или `Driven Terminal` для портового анализа); задать `Solution Frequency` в `HFSS > Design Properties`.
3. **Определение материалов.** Создать диэлектрическую подложку (например, Rogers RO4350B с εr = 3.48, tan δ = 0.0034) через `Draw > Rectangle` и `Assign Material`; металлизацию назначить как `pec` (perfect electric conductor).
4. **Построение геометрии.** Нарисовать прямоугольный патч расчётных размеров, микрополосковую линию питания, заземляющую плоскость на обратной стороне подложки.
5. **Граничные условия и возбуждения.** Назначить `Wave Port` на поперечное сечение линии питания (с опцией Adaptive Integration Line), окружить антенну `Radiation Boundary`.
6. **Настройка анализа и частотной развёртки.** Добавить `Solution Setup` с критерием сходимости (`Delta S`), добавить `Frequency Sweep` для получения характеристик в полосе.
7. **Запуск и постобработка.** Выполнить `Validate` и `Analyze`; построить S-параметры, диаграммы направленности, поля в ближней зоне.
8. **Оптимизация (опционально).** Использовать Optimetrics для настройки размеров патча и согласования.

## 8.3. Пошаговая инструкция: единичная ячейка периодической структуры (ФАР, FSS)

Для анализа бесконечной периодической решётки используется одна ячейка с граничными условиями связи и Floquet-портом:

1. **Создать геометрию единичной ячейки** с учётом периодичности (размеры ячейки соответствуют шагу решётки).
2. **Назначить Primary и Secondary границы (Linked Boundaries)** на боковые стенки ячейки для обеспечения периодичности.
3. **Разместить Floquet Port** на верхней грани ячейки (порт должен быть ориентирован вдоль оси Z). Указать направления A и B решётки, задать число мод (например, TE/TM).
4. **При необходимости настроить de-embedding** для приведения плоскости отсчёта к физической границе структуры.
5. **Задать углы падения** (θ, φ) для сканирования; для нормального падения достаточно основной моды.
6. **Настроить решатель** (Driven Modal) и выполнить расчёт S-параметров для активной ячейки.

## 8.4. Пошаговая инструкция: анализ конечной антенной решётки

Для конечных массивов доступны два основных пути:

- **Через 3D Components:** создать параметрическую модель элемента, сохранить её как 3D Component, импортировать нужное число экземпляров в новый проект и собрать массив.
- **Через `HFSS > Model > Create Array`:** после назначения Master/Slave границ (для unit cell) или при наличии готового элемента создать массив с указанием размерности, шага и границ. Команда доступна для Driven Modal и Driven Terminal после назначения master/slave границ.
- **Для больших массивов** использовать `Finite Array` с DDM/FADDM или `SBR+ Parametric Array` для электрически больших сцен.

## 8.5. Пошаговая инструкция: настройка адаптивного меширования и сходимости

1. **Создать `Solution Setup`:** правый клик по `Analysis` → `Add Solution Setup`.
2. **Задать рабочую частоту** (обычно центральную частоту рабочего диапазона). Именно на этой частоте будет строиться адаптивная сетка, и поля будут наиболее точными.
3. **Установить `Maximum Delta S`** в диапазоне 0.005–0.1 (типично 0.02 для антенн). Критерий остановки: изменение S-параметров между проходами становится меньше заданной величины.
4. **Задать `Maximum Number of Passes`** (например, 10–20). Помнить, что размер сетки и требуемая память растут с каждым проходом; завышенное значение может привести к исчерпанию ресурсов.
5. **Установить `Minimum Converged Passes`** (например, 2), чтобы анализ не остановился случайно на одном сошедшемся проходе.
6. **При необходимости использовать `Use Matrix Convergence`** для задания критериев сходимости для отдельных элементов S-матрицы.
7. **Для ускорения сходимости** применять `dummy objects` и seeding, ограничивая число проходов 6–8.

## 8.6. Пошаговая инструкция: моделирование СВЧ-фильтра (полосно-пропускающего)

На основе практики синтеза фильтров и руководств Ansys:

1. **Синтез по прототипу.** Рассчитать параметры низкочастотного прототипа (g-коэффициенты), затем перейти к параметрам связи и резонаторным длинам для выбранной топологии (combline, SIW, cavity).
2. **Создать параметрическую геометрию** резонаторов, диафрагм связи и портовых переходов. Все критические размеры (длины резонаторов, ширины ирисовых диафрагм, зазоры) вынести в переменные.
3. **Назначить `Wave Port`** на входе и выходе (или `Lumped Port` для планарных структур).
4. **Настроить решатель** (`Driven Modal`) и выполнить параметрический анализ для оценки чувствительности S-параметров к размерам.
5. **Оптимизация.** Использовать Optimetrics для настройки полосы пропускания, уровня согласования и положения полюсов. Для многопараметрических задач — MOGA или адаптивные суррогатные методы.
6. **Анализ полей** для проверки распределения токов и добротности резонаторов.

## 8.7. Использование HFSS 3D Layout для планарных структур

Для многослойных PCB и планарных антенн предпочтителен специализированный редактор:

1. **Вставить `HFSS 3D Layout`** в проект.
2. **Определить стек слоёв:** задать металлические и диэлектрические слои, их толщину, шероховатость, высоту и материал.
3. **Нарисовать топологию** (патчи, линии питания, заземление) на соответствующих слоях.
4. **Назначить порты** (обычно `Lumped Port` или `Wave Port` на краю линии).
5. **Настроить решение** как планарное ЭМ (2.5D) с частотной развёрткой; при необходимости перейти к полноволновому 3D-анализу.
6. **Запустить валидацию и анализ**, затем постобработку S-параметров и диаграмм.

# Проверенный опыт: PyAEDT 1.8.0 / AEDT 2025.1

Раздел фиксирует практические уроки, полученные при разработке реальных проектов (см. DEV_LOG.md, записи DL-01 … DL-11). **Эти знания специфичны для указанных версий**: при работе с другими версиями PyAEDT/AEDT их необходимо перепроверять.

## 9.1. Окружение и запуск скриптов

| Проблема | Решение | Источник |
|---|---|---|
| `from __future__ import annotations` → `SyntaxError` в `Tools → Run Script` | Интерпретатор AEDT (IronPython 2.7) не поддерживает future-фичи. Для скриптов, рассчитанных на `Tools → Run Script`, использовать Python 3.6-совместимый синтаксис: без `__future__`, без f-строк, без PEP 604-аннотаций | DL-01 |
| `ImportError` на `from ansys.aedt.core import Hfss` в `Tools → Run Script` | PyAEDT отсутствует во встроенном интерпретаторе AEDT. Запускать через `Automation → Run PyAEDT Script` (CPython внутри AEDT) или из внешнего CPython с установленным `pyaedt` | DL-02 |

## 9.2. Сигнатуры API PyAEDT 1.8.0

Перед использованием любого метода **сверять сигнатуру с установленной версией**. В PyAEDT 1.8.0 переименованы:

| Было (v1.5.x и ранее) | Стало (v1.8.0) | Источник |
|---|---|---|
| `Hfss(projectname=...)` | `Hfss(project=...)` | DL-03 |
| `Hfss(designname=...)` | `Hfss(design=...)` | DL-03 |
| `Hfss(new_desktop_session=...)` | `Hfss(new_desktop=...)` | DL-04 |
| `create_box(position=..., dimensions=...)` | `create_box(origin=..., sizes=...)` | DL-05 |
| `create_rectangle(position=..., dimensions=...)` | `create_rectangle(origin=..., sizes=...)` | DL-05 |

Старые имена в v1.8.0 молча попадают в `**kwargs` и не распознаются → `TypeError: unexpected keyword argument`.

## 9.3. Чтение переменных и выражений (критично)

В AEDT 2025.1 / PyAEDT 1.8.0:

- `modeler._odesign.GetVariableValue(name)` возвращает **строку с единицами** (`"3mm"`), а не число СИ. В более ранних версиях возвращал число. (DL-06)
- `GetVariableValue` **не раскрывает выражения**: для `L_line = "L_thru + dL"` возвращает саму формулу (`"l_thru + dl"`), а не вычисленное значение. (DL-07)
- `hfss[name]` возвращает **`str`**, а не объект `Variable`; `hfss[name].evaluated_value` даёт `AttributeError`. (DL-08)

**Правильный способ получения вычисленного значения:**

```python
value_si = hfss.get_evaluated_value(name)   # раскрывает выражения, возвращает число в СИ
value_mm = value_si * 1000.0                # для размерных величин
```

Для безразмерных (`eps_eff`, относительные величины) — без масштабирования. Не умножать на 1000 безразмерные переменные.

## 9.4. Геометрические операции

- `modeler.intersect([obj1, obj2], keep_originals=False)` в PyAEDT 1.8.0 **модифицирует первый объект in-place** и удаляет второй. Нового имени объекта в `object_names` не появляется. Логика «before_names / after_names / new_names = after − before» для `intersect` / `unite` / `subtract` **не работает**. (DL-09)

  **Правильно:** обрабатывать возвращаемое значение метода (`str` или `list`); имя результата — это имя первого аргумента. Для проверки существования объекта использовать возвращённое имя, а не разность множеств имён.

- При передаче строки в `create_box` / `create_rectangle` / `create_cylinder` — это **HFSS-выражение**, а не Python-выражение. Использовать только имена переменных дизайна HFSS (`W`, `pitch`, `x_margin`, `L_thru`), без Python-суффиксов `_mm`. Python-числа передавать как `float`. (DL-10)

  **Симптом ошибки:** в логе AEDT `'W_mm' is not a defined variable name in this context` — объект молча не создаётся, скрипт продолжается, что приводит к каскадным ошибкам в геометрии.

## 9.5. Wave Port и integration lines

- В PyAEDT 1.8.0 `integration_line` у Wave Port **принимает строки-выражения** HFSS-переменных наравне с числами. HFSS пересчитывает их при изменении параметров, а интеграционная линия привязана к порту и следует за ним. (DL-11 — отзыв предыдущего совета)

  ```python
  hfss.wave_port(
      assignment       = rect.name,
      integration_line = [["-pitch", "-L_thru/2", "h"],
                          ["-pitch", "-L_thru/2", "0mm"]],
      name             = exc_name)
  ```

- Следствие: после изменения `pitch`, `L_thru`, `L_line`, `y_top_res`, `h` **не требуется** пересборка портов через отдельный скрипт (`update_after_change.py` / `--update`). Ручная пересборка нужна только при изменении структуры портов (замена типа порта, геометрии поперечного сечения).

## 9.6. Общие правила работы с PyAEDT

1. **Проверять версию.** Перед написанием кода открывать `Release Notes` PyAEDT и сигнатуры используемых классов. Критичные места: конструктор `Hfss`, методы примитивов, работа с переменными, портами.
2. **Не полагаться на «здравый смысл» API.** Сигнатуры, работавшие в v1.5.x, часто переименовываются; аргументы попадают в `**kwargs` и не вызывают явной ошибки — только `TypeError` в момент вызова.
3. **Не делать выводов об ограничениях API по типам аргументов.** Пример: `integration_line` принимает не только числа, но и строки-выражения. Проверять документацию PyAEDT и примеры сообщества.
4. **Не полагаться на появление новых имён после логических операций.** `intersect`, `unite`, `subtract` в PyAEDT 1.8.0 — in-place на первом аргументе; результат возвращается, но имя — это имя первого аргумента. Проверять возвращаемое значение.
5. **Документировать отозванные советы.** При обнаружении ошибки в собственных рекомендациях фиксировать это в отдельном «Приложении. Отозванные советы» с указанием актуальной замены (как в DEV_LOG.md).
6. **Минимизировать зависимость от внутренних API.** `_odesign`, `_modeler` — внутренние и нестабильные; использовать высокоуровневые публичные методы (`get_evaluated_value`, `wave_port`, `create_box`).
